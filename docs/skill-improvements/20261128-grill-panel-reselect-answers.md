# Artifact グリル：これまでの回答をあとから再選択できるようにする（2026-11-28）

コーヒーショップのセッション（`eventstorming-20261128-1105`）で、オーナーから出た改善要望。
「これまでの回答を、あとから選び直せるようにしたい」。

## 現状（`templates/grill-panel.html`）

- 質問パネルは「自分がまだ答えていない先頭の 1 問」だけを出す。
- 回答を選び直せるのは、**直前に送った 1 問だけ**。条件は 3 つ。
  - 質問が列にまだ残っている（`stillAsked`）
  - Claude がまだモデルに反映していない（`!S.reflected[qid]`）
  - 帯の「この回答をやり直す」を押す（`S.redo`）
- 画面下の「これまでの回答」（`drawLog`）は**読むだけ**。質問文・回答・反映済みかどうかを並べるが、選び直す導線がない。
- 回答は db の `answers/<qid>--<uid>` に 1 件だけ持ち、再送信は上書き（`set`）。上書き前の回答は残らない。

## 困りごと（このセッションで実際にあったこと）

1. **回答したあとに考えが変わる**。例: 「バーチャル接客は削って」は、後の質問の自由記述で初めて出た。前に選んだ「キャラが接客する」系の回答（好みの記録、代わりの提案、支払い失敗の案内）を、画面から選び直す手段がなかった。Claude 側が確認の質問を新しく出して回収するしかなかった。
2. **選択肢の誤字や不備に後から気づく**。例: 「淹れる」が「添れる」と出た質問。回答済みの質問は表示されないので、直した選択肢で選び直してもらえない。
3. **反映済みの回答は、直前でも選び直せない**。Claude が反映を終えると、帯の「やり直す」が消える。

## 提案

### A. パネル側（優先度 高）

- 「これまでの回答」の各行に **「選び直す」** を付ける（`S.canWrite` のときだけ）。押すと、その質問を回答フォームとして開く。
  - 質問文・選択肢は、回答を送ったときの `question` と `choices` ではなく、**`grill/current` の最新の質問（無ければ回答に残した質問文）** から組み立てる。選択肢の誤字を直した場合は、直した版で選び直せる。
  - 質問が `grill/current` から外れている場合は、回答に残した `question` と `choices` だけで再現できる範囲で開く。選択肢が復元できないときは、自由記述欄だけで答えてもらう。
- 選び直した回答には **版（`rev`）と、前の回答（`prev`）** を持たせる。例: `rev: 2, prev: {choices: [...], at: "..."}`。上書きで履歴が消えないようにする。
- 選び直したあとの帯の文言は「前の回答は〇〇でした。モデルへの反映をやり直します」と、**変更前後が分かる**ようにする。

### B. Claude 側の手順（SKILL.md「回答が届いたとき」に追記）

- **「未反映」の判定を、`qid` が `reflected` に無い、から「回答の `at` が `reflected[qid].at` より新しい」にも広げる**。選び直しは、反映済みの qid に新しい回答として届くため。
- 選び直しを反映するときの手順:
  1. 該当する `decisions[]` を探す。`affects[]` と、decision の `options` のラベルが手がかり。
  2. 採用案が変わるなら、`chosen` と `adopted` を付け替える。前の採用案は `why_not` に「回答の選び直しで不採用」と書く。**decision を消さない**（理由の履歴が残らなくなる）。
  3. 前の回答から派生したシナリオ・ルール・ポリシー・ラベルを、`dmlctl refs` で洗い出して直す。
  4. 後続の決定が前の回答に依存していたら（例: 「キャラが接客する」前提の D4・D7・D16）、**黙って書き換えず、確認の質問を列の先頭に出す**。これは今の「既存の rule や decision と食い違ったら」の規則と同じ扱い。
  5. `grill/progress.reflected[qid]` の `summary` を「選び直しを反映: 前→後」に更新し、`at` を新しくする。
- 選び直しで影響が広がりそうなときは、反映前に Claude が「この選び直しで変わるもの」を `summary` に先に書き、**変更が大きい（シナリオを複数消す等）ときは確認してから反映する**。

### C. 見せ方（優先度 中）

- 「これまでの回答」に、`decisions[]` の ID（D○）を添えて、「この回答が、どの決定の元か」を見えるようにする。選び直す前に影響が分かる。
- 選び直した回答は、行に「選び直し済み（2 回目）」と出す。

## 検討が要る点

- **誰の選び直しを採るか**: 回答者が複数のとき、同じ qid で食い違う回答が並ぶ。今は「食い違いそのものを次の質問にする」。選び直しは同じ回答者の更新なので、**最新を採る**ことで足りるが、他の回答者が同じ qid に答えていた場合は食い違いとして扱う。
- **回答数の上限**: db のドキュメント数に上限（このセッションでは 25000 中の少数）がある。`prev` を回答ドキュメントに畳み込めば、ドキュメントは増えない。履歴を別ドキュメントに分けるのは避ける。
- **反映の取り消しはどうするか**: 選び直しの反映を、やはり元に戻したい場合。DML の編集は dmlctl 経由で履歴が残らない（git の履歴のみ）。**選び直し 1 回ごとに、反映前後の差分を `summary` に残す**のが最低限。

## 受け入れ条件

- 反映済みの回答でも、「これまでの回答」から選び直せる。
- 選び直しを送ると、Claude が起きて、変更前後を読んで DML を更新し、`summary` に変更前後を書く。
- 前の採用案は `why_not` に残り、decision は消えない。
- 後続の決定に影響が及ぶときは、黙って書き換えず、確認の質問が先頭に出る。
- 質問の選択肢を直したあとの選び直しで、直した選択肢が出る。

## コスト

中。パネル（`grill-panel.html`）に選び直しの導線と版管理を足す。SKILL.md「回答が届いたとき」に選び直しの手順を足す。schema と dmlctl の変更は要らない。
